# Weatherglass transition demo GIF

The GIF is **generated from the real widgets**, never hand-recorded and
never assembled from golden stills. Film mode runs the working-tree
ForecastPanel in a disposable nested GNOME Shell with fixture-forced
weather and time; the composer then samples those captures onto one
timeline and crossfades adjacent segments while **both keep playing**.

This skill owns demo-GIF generation and QA. The release skill owns
when the resulting asset is attached, published, or uploaded.

## Canonical tool

`tools/compose-demo.py` is the reusable entry point. Run it from a
worktree, never the deployment checkout:

```sh
cd extension
python3 tools/compose-demo.py
```

Missing segment captures are shot automatically through
`tools/film.sh`. Useful variants:

```sh
python3 tools/compose-demo.py --compose-only   # reuse captures; fail if absent
python3 tools/compose-demo.py --force-shoot    # recapture every segment
python3 tools/compose-demo.py --fps 10 --segment-seconds 2  # smaller file
python3 tools/compose-demo.py --encoder ffmpeg --width 0 --fps 20 --max-colors 256  # archival/full-size
```

A different arc is a sequence of repeated `--segment NAME=FIXTURE`
options. Every fixture must exist in film mode's registry, and
`--timezone` should match the fixture city so card clocks read local.

## Default Berlin day

The film-only fixtures live in
`tools/harness/probe@vijaybala.dev/film-mode.js`; do not add them to
the golden registry. They keep one city and one calendar day:

| Segment | Fixture | Berlin local time | Condition |
|---|---|---|---|
| sunny | `demo-berlin-sunny` | 2026-06-29 13:00 | clear |
| golden | `demo-berlin-golden` | actual sunset −12 min | clear |
| night | `demo-berlin-fullmoon` | 2026-06-29 23:30 | clear, 99.98% lit |
| rain | `demo-berlin-rain` | 2026-06-29 16:10 | rain |
| snow | `demo-berlin-snow` | 2027-01-19 10:20 | snow |

The default timeline is 12 fps: 0.4 s fade in, 2.5 s per segment,
0.8 s crossfades, 0.5 s fade out. Captures keep one rectangle; the
upload encode then scales to 300 px wide and uses ffmpeg-derived
scene-local 256-entry palettes with transparent frame deltas
(per-channel threshold 8). Local palettes keep daylight, rain, dusk,
and night gradients from competing for one table. That keeps the
Berlin arc near 1.6 MB instead of the roughly 8 MB
full-rate/full-size encode, with the reconstruction error bounded per
frame. Use `--palette-mode global` only when a smaller, lower-quality
single-palette encode is explicitly wanted.

## Outputs

The default work directory is `tools/out/demo-transitions/`:

- `weatherglass-demo-transitions.gif` — uploadable looping GIF
- `weatherglass-demo-transitions-contact.png` — labelled timeline picks
- `weatherglass-demo-transitions.gif.manifest.json` — fixtures,
  timeline, ffprobe result, bytes, dimensions, duration, and SHA-256
- `segments/`, `reports/`, `src/`, `frames/` — reusable capture and
  composed-frame cache

## QA before handoff

1. Read the manifest. Confirm one rectangle across segments and the
   expected size, fps, frame count, duration, bytes, and SHA-256.
2. Open the contact sheet **and the GIF itself**. Confirm the exact
   sequence sunny → rainy → golden hour → clear full-moon night.
3. For the default arc, confirm Berlin stays the city, clocks move
   forward, and the night segment clearly shows a full moon.
4. Confirm there are no black interior frames. Text ghosting is
   acceptable only inside crossfades; segment midpoints must be clean.
5. If the upload target needs a still smaller file, regenerate with
   lower `--fps`, `--width`, or shorter segments. Do not hand off an independently
   re-encoded copy whose manifest no longer describes it.

Film mode's standalone 120-frame smoke floor is calibrated for the
single-fixture MP4. During segment capture the composer may report a
film-smoke warning, but it proceeds only when the final report and the
full sampled frame window exist. Missing frames, mixed rectangles, or
failed ffmpeg/ffprobe checks are hard failures — never substitute
stills or a synthetic animation.

## Release handoff

Record the GIF path and manifest SHA-256 in the task or release notes.
If it becomes a release asset, attach the exact generated bytes and
let `skills/weatherglass-release/SKILL.md` own publication order and
URL proof. The long-form MP4 remains the manifest demo asset unless a
release plan explicitly supersedes it. Regenerate the GIF after
painter, sky, chart, or menu visual changes; a stale demo is the same
failure class as stale screenshots.
